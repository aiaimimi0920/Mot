# Mot 架构与仓库边界

当前定位更新：2026-11-13。历史拆仓记录：2026-10-07。

## 1. 标准优先，游戏专用

Mot 的目标是开放的游戏与 AI 伙伴交互协议标准及配套 SDK，不是把某个个人伙伴客户端规定为所有实现的中心。标准明确游戏、玩家和伙伴各自的权威，约束信息开放、来源与受众、行动请求和执行、授权与撤销、错误和恢复。

- 游戏决定世界状态、可公开的信息和可执行动作，并在实际投递或产生世界效果时执行约束。
- 玩家决定其伙伴接入与允许范围；需要的信息不自动成为获准的信息，用户偏好不能扩张游戏权限。
- 伙伴负责内部理解、规划和记忆实现，但不得把输入文本当作提升权限的指令。
- 协议不保证消除模型先验知识，也不以“已经撤销”声称既有知识或已发生世界效果消失。

当前只做游戏领域，不扩展到任意应用自动化。不同游戏可定义各自的情境与动作，不要求公开完整地图、存档、敌人状态或私密信息。

## 2. 逻辑分层与现有代码归属

以下是职责划分，不表示所有层已达到可发布状态，也不要求新增中心服务或立即调整 Git 仓库。

| 层 | 职责 | 当前所在与边界 |
| --- | --- | --- |
| 规范与机器契约 | 角色、权限、信息与行动语义、版本、错误、能力协商 | G2A 的规范、schema 与下一版设计；旧契约和新草案明确隔离 |
| 参考 SDK | 将协议契约变成游戏端及伙伴端可用接口 | G2A 当前 Python/JavaScript 实验实现；不能直接把文档模型当作完整新 SDK |
| 符合性验证 | 契约向量、权限负例、状态机与故障验证 | G2A 测试与设计模型；报告实际通过范围，不以测试数替代接入验收 |
| 绑定及游戏适配 | 将抽象操作映射到通信和真实游戏引擎 | G2A 实验传输及 Godot 等示例；游戏执行器仍负责世界权威与副作用 |
| 可选伙伴应用 | 模型、记忆、桌面角色、日常插件与用户体验 | MotGUI / MotCore / MotPlugin；不作为协议或 SDK 的必需依赖 |

授权、来源/受众与行动执行边界必须能被独立验证，不能只写在给模型的提示词中。核心与形象、桌面呈现、资源、Relay、持久恢复等扩展要保持显式协商；未实现扩展不得伪装成支持。

## 3. Mot 与 G2A 的关系

Mot 是本项目的对外标准方向与总入口。G2A 是现有游戏交互协议设计及实现的代码边界，其独立实现、无 Mot 账号或中心服务依赖的性质保留。根仓库继续通过 Git submodule 固定 G2A、MotGUI、MotCore、MotPlugin 的提交，各子项目拥有自己的源码和文档。

不在本次架构整理中破坏性重命名 `g2a-reference`、`g2a` 导入、G2A 路径或既有 wire 版本。未来如需命名或版本迁移，必须另有兼容映射、弃用说明和实际验证；修改 README 不会升级已安装的 SDK。

`MotCore` 指可选伙伴的智能应用运行时，不等同于协议的必需核心。其模型/记忆服务不应进入协议最低依赖图。MotGUI 的历史 `core/` 目录也不是新 MotCore 的运行时实现。

## 4. 当前实现与验收边界

- G2A 的 `0.1.0-dev` 实验规范与参考实现已存在；下一版工作草案、机器契约和假实现模型另行维护。
- 新草案模型涵盖的流程不代表现有 SDK 自动支持；真实认证、持久化、游戏端口和第三方互通需要各自证据。
- MotGUI 保留旧 Godot 客户端，MotPlugin 承接旧插件；MotCore 尚处设计阶段。
- MotGUI 中旧 `res://plugin/...`、`res://external_service_adapter/...`、`res://external_service/...` 路径不能直接访问兄弟仓库 MotPlugin。跨目录装配、打包、Python 依赖和定制引擎兼容性仍待处理，不把目录迁移称为应用联调完成。
- 最小协议闭环可以独立于旧伙伴应用验证。高级扩展按明确能力逐步实现，不以恢复全部旧客户端作为标准开发门槛。

验证报告须区分结构/契约检查、纯内存模型、参考 SDK、真实游戏适配、跨语言互通及独立第三方实现；“标准草案”“实验 SDK”“稳定发布”不混用。当前状态入口为 [G2A README](../G2A/README.md) 与 [协议开发台账](../G2A/docs/protocol/DEVELOPMENT_STATUS.md)，历史报告不替代当前运行结果。
